# PADDOCK SCOUT v1.15.0

> **名前が変わりました（v1.15.0〜）**：旧名 **SW NAS WATCH** → **PADDOCK SCOUT**。PADDOCK（競馬の下見所）シリーズとして、PADDOCK SCOUT（下見＝監視）・PADDOCK SADDLE（装鞍＝受付で整える）・PADDOCK GATE（ゲート＝会場で発走）の3本になりました。中身・使い方は同じです。新しいZIPを前のフォルダと同じ場所に展開すると、最初の起動で前の設定を引き継ぎます（前のフォルダは変更しません）。

学会などで「専用ソフトを使わず、NASの共有フォルダに演者ごとのフォルダを作ってデータを入れていく」運用のときに、
**演者フォルダの変化を読み取り専用で監視して、デスクトップ通知を出す**ツールです。
通知をクリックするとその演者フォルダの中身と、PowerPointの解析結果がアプリ内に表示されます。

**PADDOCK SCOUT はNASにも、ほかのPCにも書き込みません**（書くのは、このPCの自分の設定・ログ・解析結果だけ）。書き込みが必要な作業は、同じ画面をもとにした別のアプリで行います。

| アプリ | 使う場所 | NAS | 書き込む先 |
|---|---|---|---|
| **PADDOCK SCOUT** | 本部・PC受付の確認用 | 読むだけ | なし |
| PADDOCK SADDLE | 受付PC | 演者フォルダへ書き込む | NAS（演者フォルダの中だけ） |
| PADDOCK GATE | 各会場の発表PC | 読むだけ | このPC・バックアップPCのコピー先だけ |

- v1.12.0 までの「会場オペレーターモード」（発表PCへのコピー）は、v1.13.0 から **PADDOCK GATE** に分かれました（下記）。

## フォルダ構成（階層）

`学会名フォルダ／会場／セッション／001_演者名／…` の構成なら、**学会名フォルダを登録して「階層3」** にします（初期値は3）。

| 階層 | 構成 |
|---|---|
| 4 | 学会名／**day1**／会場／セッション／**演者**　または　学会名／会場／**1日目**／セッション／**演者** |
| 3 | 学会名／会場／セッション／**演者** |
| 2 | 会場／セッション／**演者** |
| 1 | セッション／**演者** |

左の一覧は **会場 → セッション → 演者** のツリーで並びます。

並び順は、数字を数値として比べます（「第2会場」→「第10会場」）。①〜⑳・❶〜❿ などの丸数字や全角数字も数字として扱うので、①②…⑨⑩⑪ の順に並びます。

- 会場は色分けした大きい見出しで、スクロールしても上に残ります。同じ色がフォルダ画面・変更ログにも付きます。
- 会場・セッションの見出しをクリックすると、たたむ／開くを切り替えられます（状態はPCごとに保存）。全体の開閉は一覧上部のボタンで行います。
- たたんだ中に更新があると、見出しに未確認数とコピー中の印が出ます。通知や自動表示でその演者を開いたときは、自動で展開します。
- 左上の会場選択で、**自分の会場だけ表示・通知** にできます（PCごとの設定）。

## 日ごとのフォルダ（day1・1日目・10月11日 など）（v1.9.0〜）

日ごとのフォルダがあると自動で見つけて、会場は会場として並べたまま、日で切り替えられるようにします（会場ボードとリストの「すべての日／day1／day2…」）。

- 対応する名前：`day1`・`Day 2`・`1日目`・`第2日`・`10月11日`・`2026-10-11` など（後ろに `(金)` などが付いていても可）
- 置き場所：会場の上（`学会名／day1／第1会場／セッション／演者` → **階層4**）でも、会場の下（`学会名／第1会場／1日目／セッション／演者` → **階層4**）でも、セッション名の先頭（`day1_S01 …`）でも構いません。
- 「すべての日」のときは、会場の列の中に日の区切りを入れて日ごとに並べます。
- 選んだ日はPCごとに保存されます。`day1` を選んだまま翌日になると、自動で `day2` に切り替わります。
- 会場名は「第1会場」でも「Room A」「Hall B」などでも、置き場所（階層）で判断するので同じように使えます。

## セッションの時刻と進行状況（v1.9.0〜）

セッションのフォルダ名に時刻が入っていると読み取り、進み具合を表示します。

- 読み取れる書き方：`0900-1030`・`09:00〜10:30`・`9:00-`・`9時30分〜`・`S01_0900_…`（先頭や区切りの後の4桁）など。終わりの時刻がなければ、同じ会場の次のセッションの開始までとみなします。
- 表示：**終了**（薄く表示）／**進行中・残り◯分**（緑の枠と時間のバー）／**次・あと◯分**（30分以内は黄色）。開始30分前から進行中のセッションに未受付の演者がいると、赤で「未受付 2」と出ます。
- 会場の見出しに「いま ○○ 残り25分」「次 ○○ 10:30〜（あと12分）」を出します。
- 時計はこのPCの時刻を使います。日のフォルダがある場合は「今日」の分だけ進行状況を出します（日付の名前なら今日の日付、`day1` などの名前なら選んでいる日）。

## ダブルクリックでフォルダを開く（v1.9.0〜）

会場ボード・リストで演者をダブルクリックすると、Explorer / Finder でその演者フォルダを開きます。

- 会場側への影響を避けるため、**［設定］→「Explorer / Finder で開く」をオンにしたときだけ**動きます（オフのときは、その旨を表示します）。
- 1回のクリックは今まで通り、アプリ内で中身と解析結果を表示します。

## 会場ボード（v1.7.0〜）

画面上部の［リスト｜会場ボード］で切り替えます（PCごとに保存）。**全会場を横に並べて、セッション・演者の受付状況を1画面で見渡す**表示です。

- 会場ごとに1列。列の上に「受付 12/15」と進み具合、未確認の数、コピー中の印が出ます。
- 列の中はセッションごとにまとまり（セッション名は会場色の帯・太字で表示）、演者は受付済み（緑）・コピー中（黄）・未受付（グレー）で色分け。PowerPoint解析の結果（COI・COIなし・動画・自動送り・クリック無効など）も演者の横に出ます。
- 未確認（新着）の演者は青い枠と件数で表示されます。
- 演者をクリックすると、右側にフォルダの中身と解析結果が開きます（Esc か［閉じる］で戻る）。
- 上のバーで「全体の受付数」「コピー中」「未確認」を確認でき、検索・会場の絞り込み・「未確認のみ」「未受付のみ」が使えます（会場の絞り込みと2つのチェックはリスト表示と共通）。
- 「自動表示」がオンのときは、更新があった演者まで列を自動でスクロールします（右側を開いているときは、リストと同じく中身も切り替わります）。
- **セッションの開閉**：セッション名をクリックすると閉じて演者が隠れ、コンパクトになります（閉じても見出しに受付数・未確認数・コピー中の印が出ます）。上のバーの［開く］［閉じる］で全部、各会場の見出し右のボタンでその会場のセッションをまとめて開閉できます。開閉はリスト表示と共通で、PCごとに保存されます。検索や「未受付のみ」などで絞り込んでいる間は、該当する演者が見えるよう全部開いて表示します。
- **横スクロール**：会場が画面に入りきらないときは、ボードの上に会場ナビ（◀ ▶ と会場名のチップ）が出ます。チップを押すとその会場へ移動し、いま見えている会場のチップが明るくなります。列の見出しや空いている所でホイールを回すと横に動き、← → キーでも1会場ずつ動きます（列の中のホイールは今まで通り縦スクロール）。
- 「自動表示」で更新があった演者のセッションが閉じているときは、そのセッションの見出しまでスクロールします。
- 変更ログは［ログ］で右から開きます。

## 目印のファイル（00_受付済.jpg・17_会場取得.jpg など）（v1.10.0〜・v1.11.0で拡張）

演者フォルダに **「00_受付済.jpg」「01_動画有.jpg」「17_会場取得.jpg」「18_発表終了.jpg」** のような目印の画像を置いて運用している場合、目印として読み取って表示します。目印は**データとしては数えません**（ファイル数・受付・差し替えの判断に入りません）。

| 目印（ファイル名に含まれる文字） | 扱い |
|---|---|
| 受付済・受付完了 | **受付済み**（データがまだなくても） |
| 会場取得・取得済・受取済・DL済 など | **会場取得済**（水色の行＋✓✓）＝会場側が受け取った |
| 発表終了・発表済 | **発表終了**（行を薄く表示） |
| 演題取り下げ・取り下げ・取下げ | **取り下げ**（取り消し線。受付の数・未受付から外す） |
| 会場直 | **会場直**（紫の行。データがなくても未受付にしない） |
| 変更有・演者変更 | 黄色の**注意チップ** |
| 動画有・音声有・動画のみ音声不要・PC持込・Win持込・Mac持込・持込・Backup・持込リモプレ・OP卓PC 発表者ツール・発表者ツール・ミラーリング・Mac PPT・Mac Keynote | **チップで表示**（会場ボードでは3つまで＋残りの数。全部はマウスを乗せると出ます） |

- 状態は 取り下げ → 発表終了 → 会場取得済 → 受付済み → 会場直 → 未受付 の順に優先します。
- **ファイル名（先頭の番号「00_」などを除く）が目印の文字で始まるもの**を目印にします（v1.12.0〜）。全角半角・大文字小文字・空白や「_」・括弧（【PC持込】.jpg の【】など）は区別しません。送り仮名の違い（持ち込み／持込、受け取り／受取、取り下げ／取下げ など）も同じとみなします（v1.13.2〜）。
  - 「受付済み.png」「00_受付済 - コピー.jpg」「13_変更有_2.jpg」のように、後ろに「み」「済」「- コピー」や数字が付くだけなら目印です。
  - 「受付済の資料.png」「Backup_図1.png」「受付済_演者名.jpg」のように、後ろに別の言葉が続くものは**データの画像**として扱います（データを目印と取り違えて数えない・消さないため。v1.11 までは文字が含まれていれば目印にしていました）。
  - 2つ以上に当てはまるときは長い文字のほうを使います（「08_OP卓PC_発表者ツール」は「OP卓PC 発表者ツール」）。
- 目印画像を入れたり外したりしても、「受信中」「コピー中」にはなりません（v1.11.2〜。変化は「受付済（目印）」「目印 動画有」のように通知します）。
- 目印として扱うのは、画像（png・jpg など）・テキスト・拡張子なしのファイル（20MBまで）だけです。「受付済の資料.pdf」のような普通のデータは目印になりません。
- フォルダ画面では、状態の横に目印のチップが並び、ファイル一覧では「目印：動画有」のように表示します。
- 会場の見出しとリストの上に「取得 3/12」と出ます（会場取得・発表終了の目印が1つでも見つかったときだけ）。
- 目印の文字と扱いは［設定］→「目印のファイル」で追加・変更できます。v1.10 で「受付済」「取得済」の文字を変えていた場合は、その文字も引き継ぎます。

## 受付状況

| 表示 | 意味 |
|---|---|
| 緑の行＋✓ | **受付済み**（演者フォルダにデータが1つ以上入っている、または「受付済」の目印がある） |
| 水色の行＋✓✓ | **会場取得済**（「会場取得」「取得済」などの目印がある） |
| 紫の行＋→ | **会場直**（「会場直」の目印。データは会場で受け取る） |
| 薄い行＋旗 | **発表終了**（「発表終了」の目印がある） |
| 取り消し線＋⊘ | **取り下げ**（「演題取り下げ」の目印がある） |
| グレーの行＋点線の丸 | **未受付**（フォルダが空。目印だけのときも） |
| 黄色の行＋回転マーク | **コピー中**（データを書き込んでいる途中） |

- 会場・セッション・学会の見出しに「受付 3/5」と進み具合のバーが出ます。全員そろうと緑になります（取り下げの演者は数に入れません）。
- 「未受付のみ」にチェックすると、まだデータが来ていない演者だけを表示します（取り下げ・会場直は出しません）。
- 「受付済」の目印はあるのにデータが1つもないときは「データなし」と表示します。

## 差し替えの表示（v1.8.0〜）

**パワーポイントがあった演者フォルダで、パワーポイントが追加・更新・名前変更・削除されたとき**に「差し替え」として数え、**「差替 2」** のように回数を紫のタグで表示します（会場ボード・リスト・フォルダ画面）。動画や画像をあとから足しただけ、目印ファイルを置いただけでは数えません（v1.10.0〜）。

- 通知のタイトルにも【差し替え2回目】と付きます。変更ログにも「差替2」が付きます。
- フォルダ画面には「受付 13:02」「差し替え 2回（最終 13:45）」を表示します。
- 回数と受付時刻は監視PCの `sw_nas_watch_data\track.json` に保存し、アプリを再起動しても残ります。
- このバージョンに入れる前から入っていた演者は、受付時刻が「不明」のまま、その後の変更から数えます。

## 受信中・コピー中の進み具合（v1.8.0〜）

- **NASへの受信中**：演者の行に縞模様のバーと「受信中 1.2 GB · 25 MB/s · 0:42」（受信済みサイズ・速度・経過時間）を出します。
  - コピー元の全体サイズはNASの一覧からは分からないため、%は出せません。コピーの仕方によっては最初から最終サイズで見えることがあり、そのときは速度が出ず経過時間だけになります。
- 発表PCへのコピーの進み具合（「メイン・バックアップへコピー 45%」）は、PADDOCK GATE の画面に出ます。

## 会場オペレーターモード → PADDOCK GATE（v1.13.0〜）

各会場の発表PCで、自分の会場の演者フォルダをNASからメインPC・バックアップPCへ自動でコピーする機能は、**PADDOCK GATE**（別のZIP）に分かれました。使い方は PADDOCK GATE の README を見てください。

- PADDOCK SCOUT v1.13.0 は**コピーしません**。v1.12.0 までに会場オペレーターモードを使っていたPCで v1.13.0 を起動すると、画面上部にその旨を表示します。
- PADDOCK GATE をはじめて起動すると、PADDOCK SCOUT の会場オペレーターモードの設定（監視フォルダ・会場・コピー先）と「コピー済み」の記録を引き継ぎます。
- 分けた理由：スライドショーをしている発表PCで使うアプリ（通知も音も出さない・発表PCへ書き込む）と、本部などで通知を受けて見るアプリ（どこにも書き込まない）を、設定の取り違えなく使い分けるため。

## すぐ見れる仕組み

1. コピーが始まった時点で **「受信中」** と即通知します。
2. コピーが終わり、サイズと更新日時が一定時間（既定6秒）変わらなくなったら、同じ通知を **「追加・更新＋解析結果」** に差し替えます。
3. **自動表示 ON**（初期値）の場合、更新された演者フォルダが自動で画面に出ます。マウスやキーを操作している間（15秒）は切り替わりません。

## メモ（演者フォルダの .txt）（v1.13.1〜）

演者フォルダに .txt があると、フォルダ画面の上に「**メモ**」として中身を表示します（演者・受付からの連絡など）。

- 文字コードは自動で判別します（UTF-8・BOM付き・UTF-16・Shift_JIS＝Windowsのメモ帳の古い形式）。
- 表示するのは5ファイルまで、1ファイル32KBまで。受信中の .txt は受け取りが終わってから表示します。
- NAS上のファイルは読むだけです（ほかの人の書き込み・削除を妨げない開き方）。内容は大きさ・更新日時が変わったときだけ読み直します。

## PowerPoint 解析

.pptx / .ppsx / .pptm などを自動で解析し、一覧・フォルダ画面・通知に表示します。

| 項目 | 内容 |
|---|---|
| 動画 | あり／なし。埋め込み・リンク動画・オンライン動画を区別します。リンク動画は「同じフォルダにある／見つからない／発表者PCのパス（C:\Users\…）」まで判定します。**動画の形式**（下記）も判定します |
| ハイパーリンク | あり／なし（スライド番号とURL） |
| COI | 「COI・利益相反・ディスクロージャー・Disclosure・Conflict of Interest」の文字があるか（スライド番号と該当文）。全角（ＣＯＩ）・半角カナ・大文字小文字・字間のスペースの違いは同じとみなします（「ＣＯ　Ｉ」「C.O.I」のように略語の字の間に空白や点があっても見つけます）。略さずに書いたもの（「Conflicts of Interest」の複数形・「Conflict-of-Interest」・タイトルの途中で改行した「Conflict of／Interest」・別の行に分かれた「利益／相反」・表の中の文字）も見つけます。キーワードは設定で変更できます |
| 自動送り | あり／なし（スライドと秒数）。「タイミングを使用」がオフで実際には送られない場合も区別します |
| クリック無効 | 「クリック時」がオフのスライド。自動送りもないため止まってしまうスライドは赤で警告します。キオスク（自動プレゼン）設定も検出します |

- COIが画像で貼られている場合は文字として読めないため「なし」になります。

**動画の形式チェック（v1.8.0〜）**

埋め込み動画と、同じフォルダにあるリンク動画について、会場のWindows PCで再生できるかを判定します。動画の「見出し」と形式情報（moov）だけを読み、映像データ本体は読みません。

| 表示 | 形式の例 |
|---|---|
| **動画形式NG**（赤） | HEVC（H.265。iPhone撮影に多い。Windowsは「HEVC拡張」がないと再生不可）／Apple ProRes／H.264の10bit・4:2:2・4:4:4／DNxHD |
| **動画要試写**（黄） | AV1・VP9／H.264レベル5.2以上／4096×2304超／旧形式（AVI・WMV・MPEG-2：PowerPoint 2505以降は対応が限定的）／音声がDolby Digital など |
| 再生OK | H.264（8bit・High以下）＋AAC の MP4/MOV（PowerPointの推奨形式） |

- 判定の根拠は、PowerPointの推奨形式（H.264＋AACのMP4）と、Windows標準のH.264デコーダの対応範囲（Baseline/Main/High・4:2:0・レベル5.1まで）です。会場PCに追加のコーデックが入っていれば再生できる場合もあるので、NG・要試写は試写で確認してください。
- **動画が何本あっても全部確認します**（v1.11.2〜。v1.11.0までは最初の12本、v1.11.1は60本までで、残りは何も表示されませんでした）。各動画は見出しと形式情報だけを読むので、100本以上でも読む量はわずかです（架空の120本入りで約8MB）。無圧縮で埋め込まれた動画を先に、圧縮されて埋め込まれた動画を後に確認し、読む量の合計が上限（320MB）に達したときは残りを「形式不明（省略）」と表示します。
- 動画が多いときは、再生NG・要試写・形式不明・リンク切れの動画を先に表示し、問題のない動画は「問題のない動画 113本（再生OK）を表示」に折りたたみます。
- 圧縮されて埋め込まれた長い動画で形式情報がファイルの後ろにある場合などは「形式不明」になります。
- リンク動画が `C:\Users\…`・`\\サーバー\…`・`https://…` を指しているPowerPointが「解析不可」になる不具合を修正しました（v1.11.1）。
- Keynote・旧形式(.ppt)・パスワード付きファイルは解析対象外です（その旨を表示します）。

## 会場側に影響を出さないための設計

このアプリが原因で、会場PCがNASのファイルを開けない・ダウンロードできない・差し替えられない、といったことが起きないようにしています。

**NASに対して行うこと（これだけ）**
1. フォルダ一覧・サイズ・更新日時の取得：鍵（ロック）はかけません。
2. PowerPoint解析のための読み取り：コピー完了後に1回だけ、短時間です。（同じフォルダにあるリンク動画は、形式判定のため見出しと形式情報だけを読みます）

NAS上のファイルを作る・書く・消す・名前を変える処理は一切ありません。NAS以外の場所（ほかのPCの共有フォルダなど）にも書き込みません。

**PowerPoint解析の安全策**
- **会場PCがPowerPoint / LibreOfficeで開いている間は、そのファイルに一切触れません。**
  - NAS上の鍵ファイル（`~$ファイル名` / `.~lock.ファイル名#`）があるかどうかだけを確認し、閉じられてから解析します。
- Windowsでは、他の人の読み取り・上書き・削除・名前変更をすべて許可する開き方でしか開きません。この開き方ができない環境では、普通の開き方に切り替えず、解析そのものをやめます。
- 読んでいる途中でファイルが差し替えられた場合は、その結果を捨てて読み直します。

**NASへの負荷**
- フォルダ確認に時間がかかるときは、自動で間隔を広げます（NASを使う時間は最大でも全体の1/3）。
- 起動時のまとめ解析は1件ずつゆっくり行います。

**その他**
- 「Explorer / Finder で開く」は**既定でオフ**です。Explorerは表示設定によってはサムネイル作成のためにファイルを読みに行くため、オンにするときは設定から明示的に有効にしてください。
- アプリ内からファイルを直接開く機能は**わざと付けていません**。
- 設定・ログ・解析結果は、`PADDOCK_SCOUT.exe` の横の `sw_nas_watch_data` フォルダ（ローカル）に保存します。`PADDOCK_SCOUT.exe` をNAS（ネットワーク上の場所）に置いて起動した場合は、NASに書かないよう、このPCの `%LOCALAPPDATA%\SEVENTHWELL\sw_nas_watch_data` に保存します（v1.12.0〜）。
- 設定ファイルに問題があって読めないときは、問題のある監視フォルダだけを外して起動し、元の設定は `config.bad-日時.json` として残します（設定を丸ごと初期化しません。v1.12.0〜）。
- 会場側への影響を完全にゼロにしたい場合は、［設定］で「PowerPoint解析」をオフにすると、ファイルの中身を一切開かず一覧の確認だけになります。
- より確実にするなら、NAS側に「読み取り専用のユーザー」を作り、そのユーザーで接続してください。

## 必要なもの

- **Windows 10 / 11（64bit）：インストール不要**
  - 起動用の `PADDOCK_SCOUT.exe` と、Python（`runtime\python`、python.org公式の「Windows embeddable package」3.13.16）を同梱しています。
  - フォルダの中だけで動き、レジストリやシステムには何も書き込みません。USBメモリに入れて持ち運んでも動きます。
  - 通知の表示には Microsoft Edge（Windows標準）か Google Chrome を使います。

## 起動

ZIPを**すべて展開**してから、`PADDOCK_SCOUT.exe` をダブルクリックします。

```
PADDOCK_SCOUT\
  PADDOCK_SCOUT.exe   ← これを起動
  README.md / LICENSE.txt
  runtime\           ← 動作に必要なファイル（触らない・消さない）
  sw_nas_watch_data\ ← 初回起動時に作られる（設定・ログ）
```

- 起動すると、Chrome / Edge の専用ウィンドウが開きます（v1.14.0 から、黒いコンソール画面は出ません）。
- **画面のウィンドウを閉じると、監視も終了します**（20秒ほどで止まります）。画面右上の ⏻［終了］でも止められます。
- 動作の記録は `runtime\last_run.log` に残ります。エラーで止まったときは、その内容をメッセージで表示します。
- 画面は v1.14.0 から新しくなりました（受付・監視は明るい画面、会場の発表PC用の PADDOCK GATE は暗い画面）。前の画面に戻すときは、`--legacy-ui` を付けて起動します。
- `PADDOCK_SCOUT.exe` だけを別の場所にコピーしても動きません。`runtime` フォルダと同じ場所に置いてください（デスクトップに置きたいときは、右クリック→［ショートカットの作成］で作ったショートカットを置きます）。
- ZIPを開いた画面の中から直接ダブルクリックすると、「runtime フォルダが見つかりません」と表示されて起動しません。必ず「すべて展開」してから実行してください。
- 電子署名のない社内ツールのため、初回に「WindowsによってPCが保護されました」と出ることがあります。［詳細情報］→［実行］を選んでください。展開前にZIPの［プロパティ］→「許可する」にチェックしておくと、この警告は出にくくなります。
- 削除するときは、フォルダごと消すだけで完了です。
- v1.4.0 以前のフォルダに上書きした場合は、`start_windows.bat` と `sw_nas_watch.pyc` は不要なので削除してください（設定 `sw_nas_watch_data` はそのまま引き継がれます）。

## 初回設定

1. **［設定］** を開き、学会名フォルダのパスを入力します（例 `\\192.168.0.10\share\サンプル学会`）。「階層3」のまま **［追加］→［保存］**。
2. 上部の **［通知を許可］** を押します。
3. **［テスト通知］** で、通知と音が出るか確認します。

## さらに速くしたいとき（任意・監視PCのWindows設定）

WindowsはNASのフォルダ一覧を既定で10秒キャッシュします。そのため変化に気づくまで最大10秒ほど遅れることがあります。
監視PCで管理者のPowerShellから次を実行すると、このキャッシュを無効にできます。

```powershell
Set-SmbClientConfiguration -DirectoryCacheLifetime 0 -Force
```

- 元に戻すとき: `Set-SmbClientConfiguration -DirectoryCacheLifetime 10 -Force`
- そのPCのSMB通信全体に効く設定です。効かない場合はPCを再起動してください。

## 通知が出ないとき

- Windowsの「応答不可（集中モード）」がオンだと、通知バナーは出ません（アプリ内の表示と音は動きます）。
- 通知がブロックされている場合は、Chrome / Edge のサイト設定で `127.0.0.1` の「通知」を許可してください。

## オプション

`PADDOCK_SCOUT.exe` の後ろに付けて使います（コマンドプロンプトから実行するか、ショートカットの［リンク先］の末尾に追記）。

```
PADDOCK_SCOUT.exe --root "\\192.168.0.10\share\サンプル学会" --label "サンプル学会" --depth 3
PADDOCK_SCOUT.exe --port 8791          # ポート変更（既定 8790）
PADDOCK_SCOUT.exe --no-browser         # 画面を自動で開かない（http://127.0.0.1:8790/ を手動で開く）
PADDOCK_SCOUT.exe --browser default    # 専用ウィンドウではなく既定のブラウザで開く
PADDOCK_SCOUT.exe --lan                # 同じLANの別端末から閲覧のみ可（操作は監視PCのみ）
PADDOCK_SCOUT.exe --legacy-ui          # 前の画面（v1.13 まで）で表示する
```

二重に起動した場合は、起動中の画面が開くだけです。

## v1.12.0 の主な修正（全体の点検で見つかったもの）

**受付・差し替えの数え方**
- アプリを再起動したとき、ちょうど書き込み途中だったファイルを「受付」と数え、書き込みが終わったときに「差し替え1回」と数えていた → 書き込みが落ち着くまで待つように修正。
- パワーポイントの名前変更・別フォルダへの移動・削除まで「差し替え」と数えていた → 新しいパワーポイントが入った・中身が変わったときだけ数えるように修正。
- 起動直後にNASの一部フォルダが一時的に読めないと、その演者の受付記録・差し替え回数が消えていた → 前の状態のままとみなすように修正。
- ［無視するファイル名］を変えると、その瞬間に書き込み中だったデータの受付が記録されなかった → 修正。
- 差し替えのデータを受信中の演者が「未受付」と数えられていた → もともと受付済みなら受付済みのまま数えるように修正。
- 中身が同じ演者フォルダが複数あるセッションの名前を変えると、演者の記録が入れ替わることがあった → 同じ名前どうしを優先して対応づけるように修正。

**PowerPoint解析**
- 壊れたファイル（圧縮データの破損）で「解析中」のまま止まっていた → 「解析できません（ファイルが壊れている可能性）」と表示。
- PowerPointの後からリンク動画が届いても「見つかりません」のままだった → 演者フォルダに変化があれば解析し直す。
- PowerPointで開いたまま上書き保存された新しい版が、解析されないことがあった → 修正。
- NASの一時的な不調で「開けません」になった結果を保存してしまい、ずっとそのままだった → 保存せず、接続が戻ったら・5分ごとに解析し直す。
- リンクされた音声ファイルが見つからない場合も「音声リンク⚠」と表示。Strict Open XML形式は「解析できません」と表示（以前は「動画なし・COIなし」と誤表示）。H.264のExtendedプロファイルなどは「要試写」。

**会場オペレーターモード（コピー。v1.13.0 から PADDOCK GATE）**
- コピー先で動画プレーヤーやPDFビューアが開いているファイルを、約5秒ごとにNASから読み直し続けていた → NASを読む前に置き換えられるか確かめ、失敗したら30秒〜5分あけて試す。失敗したときに空の「_差し替え前」フォルダが残る問題も修正。

- コピー先の容量不足などのエラーが「NAS側のファイルが変わった」と表示されていた → 本当の原因を表示。

**画面**
