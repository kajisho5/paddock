# PADDOCK SADDLE v1.5.1

> **名前が変わりました（v1.4.0〜）**：旧名 **SW NAS RECEPTION** → **PADDOCK SADDLE**。PADDOCK（競馬の下見所）シリーズとして、PADDOCK SCOUT（下見＝監視）・PADDOCK SADDLE（装鞍＝受付で整える）・PADDOCK GATE（ゲート＝会場で発走）の3本になりました。中身・使い方は同じです。新しいZIPを前のフォルダと同じ場所に展開すると、最初の起動で前の設定を引き継ぎます（前のフォルダは変更しません）。

学会の**受付PC**用のアプリです。演者のデータ（USBメモリ・ドラッグ＆ドロップ）を受け取り、NAS上の**演者フォルダ**へ入れます。

- 一覧・会場ボード・PowerPoint解析・目印の表示は **PADDOCK SCOUT（同梱 v1.13.0）と同じ画面**です。そこに「受付」パネルを足しています。
- **NASへ書き込むのはこのアプリだけです。** PADDOCK SCOUT（会場・本部用）はこれまでどおり読み取り専用のままです。
- 受付票の印刷機能はありません。

| アプリ | 使う場所 | NAS | 書き込む先 |
|---|---|---|---|
| PADDOCK SCOUT | 本部・PC受付の確認用 | 読むだけ | なし |
| **PADDOCK SADDLE** | 受付PC | 演者フォルダへ書き込む | NAS（演者フォルダの中だけ） |
| PADDOCK GATE | 各会場の発表PC | 読むだけ | このPC・バックアップPCのコピー先だけ |

**考え方**：フォルダだけで受付を管理している現場に、あとからシステムをかぶせるソフトです。記録の本体はあくまで**NAS上のフォルダと目印画像**（00_受付済.jpg など）で、このアプリはスタッフがExplorerでしている操作（データを入れる・目印画像を入れる／外す・演者フォルダを作る）を代わりに行うだけです。システムを使わずにフォルダだけ見ている人にも、同じように状況が分かります。

## 受付の流れ

1. 左の一覧（または会場ボード）で**演者を選ぶ**
2. データを受け取る（どれでもOK）
   - 画面に**ファイル・フォルダをドロップ**（USBのフォルダごとドロップしてもOK）
   - ［**USB・ドライブから取り込む**］→ ドライブを選んで、取り込むファイル・フォルダにチェック（［このフォルダごと］も可）
   - ［ファイルを選ぶ］／［フォルダを選ぶ］
3. いったん**この受付PCのトレイ**に受け取ります（NASにはまだ書きません）。PowerPointを先に解析して、注意点を表示します。
4. 内容を確認して［**受付する**］→ NASの演者フォルダへ書き込みます。

- 入れたくないファイルはチェックを外すか、［×］でトレイから外します。
- 何ファイルか受け取れなかった場合も、残りは受け取ります（受け取れなかったファイルの名前を表示します）。
- 大文字小文字だけが違う同じ名前のファイルを受け取ったときは、新しい方に置き換えます（Windowsでは同じファイルのため）。
- USBのショートカット（リンク）はたどりません。NASの監視フォルダやこのアプリの保存先（とそれを含むフォルダ）からは取り込めません。
- 何も選んでいないときの受付パネルに、まだNASへ入れていないデータ（トレイに残っているもの）の一覧が出ます。
- 受け取ったものが1つのフォルダにまとまっているときは、「〇〇フォルダの中身だけ入れる」（最初からオン）で、フォルダ名を付けずに中身だけを演者フォルダへ入れます。
- NASに同じ名前のファイルがあるものには「差し替え」と表示し、ボタンも［差し替えて受付する］になります。
- 書き込みが終わると、結果（書き込み済み・差し替え済み・同じ内容・使用中・エラー）を1件ずつ表示します。書き込めなかったものはトレイに残るので、原因を解消してからもう一度［受付する］を押してください。
- トレイの中身はアプリを閉じても残ります。

## 受付前の確認（自動）

トレイに入れた時点で、次のような注意を出します。

| 内容 | 例 |
|---|---|
| 発表ファイルがない | PowerPoint・PDF・Keynote が1つもない |
| PowerPointが複数ある | どれを使うか演者に確認 |
| Keynote・旧形式（.ppt） | 会場PCで開けるか確認 |
| リンク動画が受け取ったデータの中にない | 動画ファイルも受け取ってもらう |
| リンク動画が発表者PCの場所を指している | `C:\Users\…` など。会場PCでは再生できない |
| 動画の形式 | HEVC・ProResなど再生できない可能性が高い形式、要試写の形式 |
| COIの記載が見つからない | 画像で貼られている場合は検出できません |
| クリックで進めない | キオスク設定、クリック無効で自動送りもないスライド |

## NASへの書き込みのルール（会場側に影響を出さないために）

- 書き込むのは**監視フォルダの中の演者フォルダの中だけ**です。演者フォルダより上の場所には書きません。
- **NAS上のデータを消すことはありません。** 消すのは、受付パネルで外した目印画像と、失敗したときの自分の一時ファイルだけです。
- 一時ファイル（隠しファイル `.swnr_～.part`）に書き込み、**読み直して内容（SHA-256）を照合してから**、一瞬で置き換えます。書きかけのファイルが会場側から見えることはありません（PADDOCK SCOUT もこの一時ファイルは常に無視します）。
- 会場PCで**同じ名前のファイルが開かれている**（`~$ファイル名` の鍵ファイルがある）ときは、**何も書き込まずに受付を止めます**（動画だけ新しくなってPowerPointは古いまま、という状態をNASに作らないため）。閉じてからもう一度［受付する］を押してください。書き込み中に開かれた場合や、置き換えできなかった場合も上書きしません（「使用中」）。
- 演者フォルダが名前変更・削除されていたら、**フォルダを作り直さずに**止めます（受付の直前と、1ファイルごとに確かめます）。受け取ったデータはトレイに残り、「別の演者へ移す」で名前を変えた演者フォルダへ移せます。
- 前に異常終了して残った自分の一時ファイル（15分以上更新されていない `.swnr_～.part`）は、次にその演者フォルダへ書き込むときに片付けます。
- **同じ内容のファイルがすでにNASにあれば書き込みません**（「同じ内容」）。
- 上書きする前の版は、**この受付PCに保存してから**置き換えます。保存できなければ置き換えません。
- 動画などを先に、発表ファイル（PowerPoint・PDF・Keynote）を最後に書き込みます（会場側でPowerPointだけ先に届いて動画がない、という状態を短くするため）。
- NASの空き容量が足りないときは書き込みを始めません。

## 目印画像（00_受付済.jpg など）

現場で使っている目印の元画像（00_受付済.jpg 〜 18_発表終了.jpg など）を入れたフォルダを［設定］→「受付」の「目印画像のフォルダ」で指定すると、次のことができます。

- **受付したとき、「受付済」の目印画像を演者フォルダへ自動で入れます**（最初からオン。設定で切れます）。すでに受付済・会場取得・発表終了の目印があるときは入れません。**書き込めなかったファイルが1つでもあるときは入れません**（受付が終わっていないため）。
- 受付パネルの「目印」の列から、目印を**付ける**（クリック）・**外す**（付いているものをクリック → 確認）ことができます。
  - 付けるときは、元画像を**そのままコピー**します（アプリが独自の画像を作ることはありません）。同じ目印がすでにあれば何もしません。
  - 外すときに消すのは**目印画像だけ**です。演者フォルダの直下にあり、目印として認識され、しかも**目印画像のフォルダにある元画像と中身が同じもの**に限ります。中身が違うもの（データの画像かもしれないもの）は外しません。
- 目印として認識されない画像（設定の「目印のファイル」に文字がないもの）は使えません。使いたいときは、［設定］→「目印のファイル」に文字と扱いを追加してください。
- 目印画像の出し入れは「受信中」「コピー中」にはなりません。

## 演者フォルダを追加

［演者フォルダを追加］で、NASのセッションフォルダの中に演者のフォルダを作れます（セッションを選んで名前を入れる）。作ったフォルダはすぐ選ばれた状態になります。`\ / : * ? " < > |` などWindowsで使えない文字は使えません。

## USBの取り出し

［USB・ドライブから取り込む］の画面で、ドライブ名の横の［取り出す］を押すと安全に取り外せる状態にします（取り込みの途中は取り出せません）。

## 受付履歴・保存先

- 演者ごとに、いつ・どの受付PCで・何件入れたかを受付パネルの下に表示します。
- 保存先は `PADDOCK_SADDLE.exe` の横の `sw_nas_reception_data` フォルダです。
  - `received\` … 受け取ったデータ（NASへ入れたもの）の予備
  - `backup\` … 差し替える前の版
  - `staging\` … トレイ（まだNASへ入れていないもの）
  - `receipts.jsonl` … 受付の記録（目印を付けた・外した記録も含む）
- 受付PCの空き容量に注意してください（受け取るたびに予備が残ります）。

## 設定

［設定］で次の項目を変えられます（発表PCへのコピーは PADDOCK GATE の役目で、受付アプリではしません）。

- 受付先のNASフォルダ（学会名フォルダ）と階層（PADDOCK SCOUT と同じ）
- **NASへ書き込んだあと、読み直して内容を照合する**（おすすめ・最初からオン）
- **受け取ったデータと、差し替える前の版をこのPCにも残す**（おすすめ・最初からオン。オフのときは、差し替え前の版を残さずに置き換えます）
- **受付PCの名前**（受付履歴に記録されます。受付PCが複数あるときに付けてください）
- 目印のファイル・COIの文字・通知など（PADDOCK SCOUT と同じ）

受付PCは最初、**通知と音がオフ**の状態で始まります（自分が書き込んだ変化は自動で既読になります）。

## PADDOCK SCOUT・PADDOCK GATE との併用

- 同じPCで同時に起動できます（画面のアドレスが別：WATCH は `http://127.0.0.1:8790/`、RECEPTION は `http://127.0.0.1:8795/`、OPERATOR は `http://127.0.0.1:8797/`）。設定も別々に保存します。
- 本部の PADDOCK SCOUT には、受付で入れたデータが「追加」「更新（差替）」として表示されます。
- 会場の PADDOCK GATE は、受付で入れたデータを、NASへの書き込みが終わった時点で発表PC・バックアップPCへコピーします。

## 必要なもの・起動

- Windows 10 / 11（64bit）。インストール不要（Python 3.13.16 の embeddable package を同梱）。
- ZIPを**すべて展開**してから、`PADDOCK_SADDLE.exe` をダブルクリックします。Chrome / Edge の専用ウィンドウが開きます（v1.3.0 から、黒いコンソール画面は出ません）。
- 画面のウィンドウを閉じても裏で動いています（NASへの書き込みの途中で止まらないように）。もう一度起動すると画面が開きます。止めるときは画面右上の ⏻［終了］を押します（書き込みの途中は終了できません）。
- 動作の記録は `runtime\last_run.log` に残ります。エラーで止まったときは、その内容をメッセージで表示します。
- 画面は v1.3.0 から新しくなりました（明るい画面）。前の画面に戻すときは `--legacy-ui` を付けて起動します。
- この画面は受付PCの中だけで使えます（同じLANの他のPCからは開けません）。
- 電子署名のない社内ツールのため、初回に「WindowsによってPCが保護されました」と出ることがあります。［詳細情報］→［実行］を選んでください。

```
PADDOCK_SADDLE\
  PADDOCK_SADDLE.exe   ← これを起動
  README.md / LICENSE.txt
  runtime\               ← 動作に必要なファイル（触らない・消さない）
  sw_nas_reception_data\ ← 初回起動時に作られる（設定・受付データ）
```

## オプション（コマンドラインから起動する場合）

```
PADDOCK_SADDLE.exe --root "\\192.168.0.10\share\学会名" --depth 3
```

| オプション | 内容 |
|---|---|
| `--root` | 受付先の学会名フォルダを追加（複数可） |
| `--depth` | 演者フォルダの階層（学会/会場/セッション/演者 なら 3） |
| `--port` | 画面のポート番号（既定 8795） |
| `--data-dir` | 設定・受付データの保存先 |
| `--drive` | 取り込み元として一覧に出すフォルダ（任意・複数可） |
| `--no-browser` | 画面を自動で開かない |
| `--legacy-ui` | 前の画面（v1.2 まで）で表示する |
